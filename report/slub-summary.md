## 二、分配器设计思路

### 1. 两层分配结构

底层继续通过 `alloc_pages()`、`free_pages()` 管理物理页；SLUB 在这些页面内管理不同大小的对象。SLUB 不替换 `pmm_manager`，也不借用 `Page` 中原有字段保存对象状态。

### 2. 小对象按尺寸分类

采用 16、32、64、128、256、512、1024、2048 字节八个尺寸类别，请求向上选择最小可容纳的类别。每个 slab 使用一页，同一 slab 中所有槽位大小相同。

每类缓存维护有空位的 `partial` 链表和已满的 `full` 链表。slab 头部保存所属缓存、容量、在用数量、空闲对象链表及缓存链表节点。

### 3. 元数据与用户区分离

本工程页大小为 4096 字节，页内头部对齐后占 64 字节，对象区从其后开始，保证至少 16 字节对齐。

```text
一页 slab：[页头及对齐填充，64字节][等长对象槽位][尾部余量]
```

容量按 `(4096 - 64) / 槽位大小` 向下取整计算，不能忽略头部。空闲槽位用自身空间保存 next 指针；分配给用户后，整个请求区间均可写，分配器不再依赖该槽位原先的 next 内容。

### 4. 分配、释放和状态转换

小对象优先从 partial slab 的空闲链表取出；没有可用 slab 时申请新页。slab 分配满后移入 full，满 slab 释放对象后移回 partial。

最后一个对象释放时，先解除缓存链表引用，再立即归还整页。这样既能复用空闲槽位，也避免留下指向已归还页面的节点。

### 5. 大对象与失败处理

超过 2048 字节的请求走连续页路径，首页保存头部，用户地址指向头部之后。合法分配起始地址按页向下对齐即可找到所属头部。

Buddy 会将页数向上取整到二次幂，但释放必须传原始请求页数，因此头部记录原始页数。例如请求 8192 字节，加头部后需要 3 页，Buddy 实际占用 4 页，释放仍传 3。

尺寸计算先检查溢出；零尺寸、无法满足的请求返回 NULL，NULL 释放无操作。不承诺清零，也不扩展重复释放、非法指针检查或 SMP 支持。

## 三、测试方向

测试使用静态记录保存存活对象，不通过 SLUB 分配测试自身的管理结构。根据对象编号、分配序号和字节偏移生成数据模式，写满请求区间；每次操作后复核所有存活对象。

| 测试方向 | 核心检查 |
|---|---|
| 基本行为 | 非空、16字节对齐、零尺寸分配、NULL释放，不依赖初始清零 |
| 类别和跨页边界 | 全部类别的 B−1、B、B+1，非整齐大小及页边界附近；完整区间读写 |
| 数据隔离 | 多个同类和异类对象同时存活，区间不重叠，操作其他对象后内容不变 |
| slab 状态转换 | 填满两个 slab 后释放并重新分配，再触发第三个 slab，避免其他 partial slab 掩盖转移错误 |
| 释放顺序与复用 | 顺序、逆序、交错释放，多轮重复，以及固定种子的有界随机操作 |
| 大对象 | 多个多页对象同时存活，与小对象交错释放，核对 Buddy 的实际页数取整 |
| 页面回收 | 每组恢复空闲页基线；非最后对象释放不得还页，最后对象释放必须立即还页 |
| 失败与恢复 | 接近 SIZE_MAX 的请求，以及新建小 slab、满 slab 扩展、大对象取页失败后的数据保持和恢复 |

取页失败采用仅在测试构建启用的一次性故障注入，并断言故障确实被消费，避免请求从已有空闲槽位成功分配而漏测失败路径。测试不耗尽整个内核，也不修改底层空闲链表。

复用检查不要求返回某个指定旧地址，而通过数据正确、区间隔离和页数变化判断。各组对象数量和操作次数均有上界，失败信息包含阶段及关键参数。

## 四、本次验证结果

实际编译并在 QEMU 中启动，Buddy 九组自检和 SLUB 八组测试通过：1831 次成功分配、1831 次释放、5502 轮存活内容复核，最终恢复到 31905 个空闲页。普通构建关闭测试辅助入口后也编译启动通过。

Buddy配置的课程评分为10/20，Best-Fit验收配置为20/20；两种配置下SLUB八组测试均通过。完整命令、日志和截图见[主报告第5.3节](report.md#buddy-slub-validation)。
