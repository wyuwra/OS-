# Lab2 Buddy 伙伴分配器：设计与测试说明

负责人：2412737-罗元伟。

Buddy负责连续物理页的分配、拆分与合并，为上层SLUB提供页资源。本文说明当前实现及九组内核自检。

## 一、模块位置与职责

核心文件为 [`buddy_pmm.c`](../lab2_new/kern/mm/buddy_pmm.c) 与 [`buddy_pmm.h`](../lab2_new/kern/mm/buddy_pmm.h)。
在 [`pmm.c`](../lab2_new/kern/mm/pmm.c) 的 `init_pmm_manager()` 中选择 `buddy_pmm_manager`，实现现有页管理接口：初始化、登记可用页、分配连续页、释放页、统计空闲页和自检。

Buddy 管理物理页，SLUB 在其上管理字节级对象。二者通过 `alloc_pages()`、`free_pages()` 衔接，SLUB 不替换 Buddy 的管理器注册。

## 二、设计思路

### 1. 按阶组织空闲块

阶数 order 对应 `2^order` 个连续物理页，每个阶维护一个独立的双向空闲链表。静态链表数组覆盖 `size_t` 可表示的阶数，实际最大阶根据 `npage - nbase` 计算。

块对齐、伙伴定位均基于绝对物理页号 PPN，不使用 `Page *` 指针数值作为物理坐标。一个 order 阶块的起始 PPN 必须按 `2^order` 对齐，且整块位于管理范围内。

### 2. 初始化与内存区间交付

`buddy_init()` 初始化各阶链表和计数。`buddy_init_memmap(base, n)` 先核实整段页面仍为保留状态，再清理描述符并登记空闲块。

任意起止位置的区间按“当前起点对齐且不超出剩余长度”的最大二次幂块逐段拆分，因此不要求整段长度为二次幂，也不会丢弃尾部可用页。可合并的相邻交付区间通过同一伙伴合并逻辑连接；保留页或未交付的空洞阻止合并。

### 3. 分配与拆分

`buddy_alloc_pages(n)` 将正数页请求向上取整到最小二次幂，找到目标阶或更高阶的第一个非空链表。若取到较大块，逐级二分：保留下半块继续拆分，把上半块登记到对应阶，直到得到目标块。

分配计数扣除实际取整后的页数。没有合适连续块、请求超过可用量或无法安全表示时返回 NULL；这些失败发生在摘链之前，不改变已有状态。`n == 0` 属于前置条件违反，会触发断言。

### 4. 伙伴定位与递归合并

order 阶块的伙伴起始页号为：

```text
buddy_ppn = block_ppn XOR (1 << order)
```

释放时，仅当伙伴处于管理范围、同阶、空闲且不是保留页，才摘除伙伴并合并成高一阶块，继续向上尝试。
物理上相邻的同大小块不一定是伙伴；它们必须属于同一个对齐父块，不能只凭地址连续就合并。

### 5. 描述符状态与释放约定

| 页面角色 | 实际记录方式 |
|---|---|
| 空闲块首页 | 设置 `PG_property`，`property` 保存阶数，`page_link` 挂入该阶空闲链表 |
| 已分配块首页 | flags 的 bit 2 表示已分配，`property` 保存阶数，flags 高位编码原始请求页数 |
| 已交付块内部页 | flags、property 为零，链表节点自链接 |
| 保留或未交付页 | 保留状态使其不能作为可合并空闲块 |

这套私有约定由 Buddy 自己管理，SLUB 不读写或借用这些字段。

释放必须调用 `free_pages(原始首页, 原始请求页数)`。例如申请 3 页实际占用 4 页，释放仍传 3；Buddy 验证原始请求记录后归还完整的 4 页。
不能传取整后的页数，也不支持部分释放、重复释放或错误首页。`nr_free_pages()` 统计实际空闲页数，不是空闲块数。

实现沿用当前实验的串行调用环境，不额外提供 SMP 同步。

## 三、测试设计与覆盖

测试入口是管理器的 `buddy_check()`，由 `pmm_init()` 内的 `check_alloc_page()` 调用，代码与分配器位于同一 C 文件。

测试先从真实分配器借用对齐的 128 页，用前 64 页作为测试区，后 64 页作为阻止跨界合并的保护区；另外保留一个独立的外部分配，检查测试不能破坏其描述符和引用计数。
测试期间保存并临时隔离真实空闲链表，结束时恢复描述符、链表、计数和最大阶，再归还借用页。

独立的交付映射、页所有者映射和分配记录检查每次操作结果；页数取整使用乘法，伙伴判断使用对齐父区间，与实现中的移位和 XOR 分开计算。
结构审计检查链表双向关系、块对齐、范围、页面覆盖不重叠、描述符状态及空闲页计数。大数组放在静态存储中，测试区和记录数都有上界。

| 测试组 | 覆盖方向 | 能发现的问题 |
|---|---|---|
| 1 初始化与边界 | 单页、未对齐起止、多段交付、保留空洞、不同顺序交付相邻区域 | 丢失尾页、错误越界合并、重复登记、区域拆分错误 |
| 2 尺寸取整与隔离 | 1、2、4、8 页及 3→4、5→8 页，检查分配范围和计数 | 按原始请求量而非实际占用量计数、分配重叠 |
| 3 多级拆分 | 从大块拆出单页，再用完各个剩余半块 | 丢失拆分余块、错误阶数或链表维护 |
| 4 伙伴合并 | 成对释放，顺序、逆序和交错释放后重新申请整块 | 合并遗漏、释放顺序依赖、无法恢复大块 |
| 5 相邻但非伙伴 | 释放相邻同阶非伙伴块，验证不能合并 | 把普通相邻块误判为伙伴 |
| 6 空洞和已占用屏障 | 不同阶块、未交付空洞、仍被占用的中间块 | 跨空洞或存活块合并、错误满足大块请求 |
| 7 失败原子性 | 受控测试区耗尽、超大请求、取整后放不下，失败前后比较状态 | 整数边界错误、失败改变链表、计数或已有分配记录 |
| 8 可复现混合序列 | 混合尺寸分配释放，最终恢复完整 64 页块并重新申请 | 复杂生命周期导致的状态损坏或累计泄漏 |
| 9 真实分配器恢复 | 恢复借用区和真实链表，检查外部分配，再执行正常申请释放 | 测试破坏外部状态、只恢复计数却没有恢复实际空闲布局 |

非法参数触发断言不属于上述正常启动九组的通过范围，不将其混同于返回 NULL 的资源不足行为。

## 四、运行结果

在GCC 13.2.0、QEMU 4.1.1、128 MiB RAM下，当前源码的Buddy配置完成九组自检，共303次测试区操作、326次结构审计，随后SLUB八组测试也通过，最终恢复至31905个空闲页。

```text
BUDDY CHECK ALL PASSED (9 groups, 303 arena operations, 326 structure audits)
check_alloc_page() succeeded!
SLUB CHECK ALL PASSED (8 groups, 1831 allocations, 1831 releases, 5502 content audits, 31905 free pages)
```
