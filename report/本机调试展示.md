# 本机 Lab2 调试展示

源码目录：`/home/sven1/course-project/os/OS-/lab2_new`。默认分配器为 Best-Fit。
本机已验证 GCC 15.1.0、RISC-V GDB 16.3、宿主 GDB 15.1 与 QEMU 4.1.1。采用两个 GDB：宿主 GDB 直接启动 QEMU，内核 GDB 连接其调试接口。

## 终端一：宿主 GDB 启动 QEMU

在 WSL 终端中执行：

```bash
cd /home/sven1/course-project/os/OS-/lab2_new
export PATH="/home/sven1/course-tools/riscv-elf-toolchains/bin:/home/sven1/course-tools/qemu-4.1.1-lab1/install/bin:$PATH"
make -j2
riscv64-unknown-elf-nm bin/kernel | grep ' kern_init$'
gdb --args /home/sven1/course-tools/qemu-4.1.1-lab1/build/riscv64-softmmu/qemu-system-riscv64 -L /home/sven1/course-tools/qemu-4.1.1-lab1/install/share/qemu -machine virt -nographic -bios default -device loader,file=bin/ucore.img,addr=0x80200000 -gdb tcp:127.0.0.1:1234 -S
```

在宿主 GDB 中执行以下命令，然后保持运行，转到终端二。地址使用上面 `nm` 查询的值，本次为 `0xffffffffc02003f4`。

```gdb
set pagination off
handle SIGPIPE nostop noprint
break riscv_cpu_tlb_fill if address == 0xffffffffc02003f4
run
```

## 终端二：内核 GDB

```bash
cd /home/sven1/course-project/os/OS-/lab2_new
export PATH="/home/sven1/course-tools/riscv-elf-toolchains/bin:$PATH"
make gdb
```

在内核 GDB 中执行：

```gdb
tbreak kern_init
continue
```

此时终端一应在取指的转换函数中停住。内核 GDB 会等待 QEMU 响应，切回终端一进行观察。

## 取指与页表观察

在终端一的宿主 GDB 中执行：

```gdb
bt 6
tbreak get_physical_address if addr == 0xffffffffc02003f4
continue
p/x env->satp
tbreak cpu_helper.c:254 if addr == 0xffffffffc02003f4
continue
p/x pte_addr
p/x pte
p idx
finish
p/x pa
```

本次根页表为 `0x80205000`，第 511 项位于 `0x80205ff8`，内容为 `0x200000cf`；返回的 4 KiB 页基址为 `0x80200000`，加偏移 `0x3f4` 后是 `0x802003f4`。`finish` 显示函数返回值为 0；此时调用者可能尚未完成 `ret` 赋值，需要再单步后查看该局部变量。

TLB 填充、命中、数据写入和 Bare 观察的实际断点及数值保存在[宿主 GDB 日志](evidence/best-fit-local-20261021/mmu-host.log)、[内核 GDB 日志](evidence/best-fit-local-20261021/mmu-guest.log)和[Bare/数据写入日志](evidence/best-fit-local-20261021/mmu-bare-store-host.log)。Bare 对比使用全新启动，内核地址随重新编译而更新。

结束展示时，先在宿主 GDB 停止并 `quit`，确认结束其启动的 QEMU，再退出内核 GDB。
